## 🏗️ ARCHITECTURAL DECISIONS (ADR)

### Tech Stack

**Frontend:**
- Framework: Next.js 15 + TypeScript strict mode
- UI Library: shadcn/ui (React components)
- Styling: Tailwind CSS (minimal, trust-focused design for legal context)
- State Management: React Context (simple, no complex state needed for MVP)

**Backend:**
- Runtime: Node.js 20.x (Vercel serverless functions)
- Framework: Next.js 15 API Routes
- Database: Supabase PostgreSQL + pgvector extension (vector search for RAG)
- ORM: Supabase client (direct SQL + row-level security)

**AI/LLM:**
- LLM: Claude 3.5 Sonnet API (zero-retention DPA) OR Ollama local (llama3.2)
- Embeddings: OpenAI text-embedding-3-small OR local multilingual-e5
- RAG Pipeline: document chunking (500-1000 tokens) → embedding → hybrid retrieval (70% vector + 30% BM25) → LLM synthesis

**Infrastructure:**
- Hosting: Vercel (Next.js frontend + serverless API routes)
- Database: Supabase Cloud (free tier → paid when scaling)
- Storage: Supabase Storage (for uploaded PDFs/HTML documents)
- CI/CD: GitHub Actions (build + lint + type-check on PR)

### Architecture Pattern
- **Chosen:** Serverless Monolith (Next.js app with API routes + Supabase backend)
- **Reason:** Simplicity over microservices. All-in-one Next.js reduces operational complexity. RAG pipeline is self-contained (ingestion → retrieval → synthesis). Internal use = low concurrency, no need for distributed architecture.
- **Trade-offs Accepted:**
  - ✅ **Pros:** Fast iteration, zero DevOps overhead, cost-effective (<€50/month), standard startup stack
  - ❌ **Cons:** Vendor lock-in (Vercel + Supabase), scaling limits (acceptable for internal use), cold starts (mitigated by Vercel edge caching)

### Authentication Strategy
- **Approach:** Supabase Auth (session-based authentication)
- **Reason:** Built-in with Supabase, RLS (row-level security) native integration, no additional auth provider needed
- **OAuth Providers:** None for MVP (internal use, email/password sufficient)
- **Session Management:** Supabase sessions (JWT stored in httpOnly cookies)
- **Admin Role:** Simple role column in users table (admin=true for document ingestion access)

### Data Modeling
- **Primary Entities:** User, Document, Embedding, Conversation, Message, Citation
- **Key Relations:**
  - User → Conversations (1:N)
  - Conversation → Messages (1:N)
  - Document → Embeddings (1:N)
  - Message → Citations (N:M via sources_cited join table)
- **Vector Index:** pgvector index on embeddings.vector (HNSW algorithm for fast similarity search)
- **BM25 Index:** PostgreSQL full-text search (tsvector) on embeddings.text for keyword matching
- **Migrations Strategy:** Supabase migrations (SQL-first, version controlled)
